# 网页版旅行档案与 PDF 导出设计

## 目标与动机

为“智游足迹”本地网页版增加面向个人长期留档的旅行报告。用户可以把一趟已经结束的行程导出为单独档案，也可以把全部已经结束的行程汇总为一本旅行总档案，并通过浏览器的打印能力保存为固定版式 PDF。

报告强调完整、可追溯，而不是面向公开分享的精简展示。它需要同时保存行程路线、攻略、花销、足迹和 AI 检索依据，并明确报告生成时间和收录边界。

## 范围

本阶段实现：

- 已结束行程的单趟档案预览和打印。
- 仅包含已结束行程的旅行总档案预览和打印。
- A4 纵向专用打印版式、稳定分页和浏览器“打印/保存为 PDF”入口。
- 对现有行程、AI 攻略、花销和足迹数据的只读聚合。
- 无数据、加载失败和行程尚未结束时的明确页面状态。

本阶段不实现：

- Word、Excel、JSON 或其他导出格式。
- 网站内保存 PDF 文件、导出历史、导出次数或报告快照。
- 云端存储、分享链接、邮件发送或跨设备同步。
- 未来或正在进行的行程导出。
- 高德地图图形、地图截图或依赖联网地图资源的打印内容。
- 照片、相册或游记编辑；当前项目没有相应业务数据。

## 已比较的实现方式

### 方案一：浏览器打印为 PDF（已选择）

网站生成只读、固定版式的打印预览页，用户点击“打印/保存为 PDF”后使用浏览器打印窗口保存文件。

优点是能直接使用本机中文字体和浏览器成熟的分页能力，不需要大型运行依赖；预览内容与最终打印内容一致，长篇攻略、表格和链接更容易维护。缺点是最后一步需要用户在系统打印窗口中选择保存位置。

### 方案二：调用本机 Edge 自动打印

服务端启动本机 Edge 的无界面打印模式并直接生成文件。操作步骤更少，但依赖 Edge 的安装位置、版本、进程权限和命令行行为，会给当前无第三方运行依赖的本地项目增加脆弱的系统耦合。

### 方案三：Node.js 直接绘制 PDF

服务端使用 PDF 库排版并嵌入中文字体，可实现一键下载。它需要新增 PDF 依赖和可合法嵌入的中文字体资产，长表格、链接、目录和多页攻略的排版维护成本最高，也会形成一套与网页预览分离的渲染实现。

选择方案一，因为它最符合本项目“同一台电脑、本机使用、低依赖”的边界，同时能提供可靠的中文长文档留档。

## 用户入口与流程

侧边栏新增“旅行档案”入口，进入旅行总档案介绍页。页面显示可收录的已结束行程数量、收录截止日期，并提供“预览旅行总档案”。

已结束行程的详情页新增“导出行程档案”。尚未结束的行程不显示可执行导出按钮，而是说明“行程结束后可生成档案”。结束判定沿用现有行程状态规则：行程结束日期必须早于服务端当天日期；结束日期等于当天时仍不算已结束。

用户点击预览后，在新浏览器标签页打开专用打印路由：

- 单趟档案：`#/reports/trips/<tripId>/print`
- 总档案：`#/reports/archive/print`

预览页不显示网站侧栏和编辑控件，只显示档案正文、返回说明和“打印/保存为 PDF”按钮。点击按钮调用浏览器打印窗口。原行程页面保留在原标签页，不丢失其页面状态。

每次打开或刷新预览都重新读取当前数据库。预览加载完成后形成当前标签页内的只读快照；其他标签页之后发生的修改不会悄悄改变已经显示的内容，用户主动刷新才重新生成。

## 单趟行程档案内容

每份单趟档案包含以下固定章节：

1. **封面与档案信息**：行程名称、起止日期、旅行天数、人数、城市路线、预算、实际花销、报告生成时间和数据库版本。
2. **行程概览**：各城市停留范围、预算执行状态和整体摘要。
3. **攻略与每日安排**：按日期展示当前保存的关联攻略活动、注意事项和引用来源编号。若攻略经过人工编辑，显示“已人工修改”。由于攻略转换成正式行程后允许两边独立修改，附录同时保留“创建正式行程时的攻略快照”和“模型原始输出”，并明确标注三种版本的含义；内容相同时可以合并展示并注明一致。
4. **花销统计**：总额、预算余额或超支金额、按分类统计、按城市统计，并单独列出“不属于具体城市”的整趟花销。
5. **逐笔花销**：日期、分类、城市归属、金额和备注，使用现有稳定排序规则。
6. **本次足迹**：只列出与这趟行程关联的自动足迹，包括城市、省份、到访日期和备注；不绘制地图。
7. **AI 与检索来源附录**：平台、模型、攻略生成和更新时间，以及每条来源的标题、安全的 HTTP(S) 链接、摘要、文章发布日期和检索时间。

没有 AI 攻略、花销或关联足迹时，保留对应章节并显示“暂无相关记录”，不伪造内容，也不隐藏整章。报告不得包含 API Key、密文、数据库路径、内部操作编号、内部备份编号或底层错误信息。

## 旅行总档案内容

旅行总档案只收录生成当天已经结束且仍存在的正式行程。正文按开始日期倒序、再按稳定标识排序；目录先按年份分组，每趟行程从新页开始。

总档案结构为：

1. **总封面**：标题、生成时间和收录截止日期。
2. **卷首总览**：已结束行程数、累计旅行天数、累计花销、到访省份、到访城市和到访次数。累计旅行天数按每趟行程的自然日数相加；两趟行程日期重叠时仍分别计入，不计算去重后的日历天数。
3. **汇总统计**：按年份、花销分类和明确归属城市的花销汇总；整趟花销单独列示，不自动分摊。
4. **年度目录**：按年份列出行程名称、日期、路线和总花销。
5. **行程正文**：每趟完整复用单趟档案的章节，不使用精简版。
6. **卷末索引**：年份索引、城市索引和全部足迹列表。

卷末的全部足迹列表包含现存的手动足迹、关联正式行程的自动足迹，以及行程删除后保留的历史足迹。每趟行程正文只包含与该行程关联的足迹，避免把手动补录或其他行程记录错误归入某一趟旅行。

## 数据聚合与一致性

服务端新增只读的旅行档案聚合服务，复用现有行程、花销、AI 攻略和足迹存储，不新增业务表。服务提供两种只读结果：单趟档案数据和总档案数据。

每次生成在一个数据库只读事务中完成，统一捕获：

- 服务端当天日期和生成时间；
- 符合结束条件的行程；
- 对应的当前行程内容、花销、关联 AI 攻略、创建行程时的转换快照和足迹；
- 总档案所需的全局足迹和汇总数据。

这样可避免报告在聚合期间混入一半旧数据、一半新数据。服务端必须再次校验单趟行程已经结束，不能只依靠前端隐藏按钮。未知行程返回不存在；未结束行程返回明确的不可导出错误。

返回给浏览器的是专用报告读模型，不直接暴露存储对象。读模型只包含渲染所需字段，并使用现有领域规则计算日期、金额、分类和城市展示值。链接只允许安全的 HTTP(S) 来源；不安全或损坏的历史链接只作为不可点击文本说明，不形成可执行链接。

## 页面与打印版式

预览页使用独立的打印容器和暖色屏幕预览，实际打印为白底、深色文字。默认纸张为 A4 纵向，使用本机中文系统字体栈，不加载远程字体、图片或地图资源。

打印规则包括：

- 封面、总目录和每趟行程正文从新页开始。
- 章节标题避免落在页尾，活动条目和来源条目尽量整体跨页。
- 长花销表格允许跨页，并在新页重复表头。
- URL 可以换行，不能撑破页面。
- 交互按钮、返回提示和错误操作在打印时隐藏。
- 使用 CSS 分页计数器输出页码；浏览器不支持总页数计数时，至少保留当前页码和生成时间，不以错误的总页数占位。
- 使用打印色彩调整保证浅色分隔线可见，但不依赖背景色表达任何关键信息。

总档案可能很长，但首版不设置人为的行程数上限。页面先显示加载状态，完整数据成功后再开放打印按钮；加载失败时不允许打印半份报告。

## 错误与边界状态

- 没有任何已结束行程时，总档案页面显示空状态，不打开空白打印窗口。
- 单趟行程不存在或尚未结束时，显示原因和返回入口。
- 任一聚合读取失败时，显示安全错误并提供重试；不得渲染部分报告或自动调用打印。
- 浏览器取消打印不产生任何网站状态变化，也不记录“导出成功”。
- 打印窗口、保存位置、文件名和打印机错误由浏览器处理；网站不声称能够确认 PDF 已保存。
- 建议文件名显示在预览页：单趟为 `旅行档案-<行程名称>-<结束日期>.pdf`，总档案为 `旅行总档案-截至<收录日期>.pdf`。由于采用浏览器打印，网站只提供建议，不能强制系统使用该文件名。

## 安全与隐私

报告 API 继续受本机 Host 和同源请求保护，只提供 GET 读取。页面所有业务文本按纯文本渲染，不执行行程备注、AI 内容或来源摘要中的 HTML。外部来源链接使用 `noopener noreferrer`，且打印不触发来源访问。

报告不读取或展示模型 Key、地图 Key、安全密钥、加密设置、数据库路径、备份位置和服务器日志。打印页面不会自动请求来源网站、高德地图或其他第三方资源。

## 验收标准

- 已结束行程能够从详情页在新标签页打开完整单趟预览；未结束行程不能绕过服务端生成报告。
- 总档案只收录结束日期早于服务端当天的行程，排序、数量、总额和分类汇总准确。
- 单趟报告完整展示当前路线、当前关联攻略、创建行程时的转换快照、模型原始输出（如适用）、逐笔花销、关联足迹和来源。
- 总档案的每趟正文与同一时刻的单趟档案口径一致，并额外包含全局汇总和全部足迹索引。
- 缺失 AI、花销或足迹时显示真实空状态；恶意文本不会执行，非法来源不会成为链接。
- A4 打印预览中封面、目录、章节、长表格和长 URL 不截断，交互控件不进入 PDF。
- 取消打印、重复预览和刷新不会写数据库，也不会产生导出历史。
- 自动化测试覆盖结束边界、事务一致性、聚合计算、敏感字段排除、路由、页面状态和打印 DOM。
- 使用隔离 QA 数据在内置浏览器验收单趟和总档案，包括长攻略、多页花销、无 AI 行程和未结束行程。

## 实现者可自行确定的细节

- 报告读模型和服务文件的准确命名，只要保持只读并与现有服务分层一致。
- 预览按钮和侧边栏入口的具体暖色样式；用户已说明 UI 后续会统一调整。
- 在 CSS 支持范围内的字号、页边距和分页微调，只要 A4 可读性和验收标准不变。
- 无法强制浏览器保存文件名时的提示文案。
