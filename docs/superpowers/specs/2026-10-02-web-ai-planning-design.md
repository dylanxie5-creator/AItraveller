# 智游足迹网页版：第二部分 AI 检索与旅游规划设计

日期：2026-10-02。状态：对话内功能设计已获用户“符合”确认；本书面设计待用户审阅，尚未编写实施计划或产品代码。

## 1. 意图、已确认选择与范围

为个人本机网站增加真正联网检索的旅游规划：用户使用自己的 API Key，自选 DeepSeek、智谱、小米 MiMo、Kimi 或 Qwen 文本模型；获取有实际检索来源的多城市攻略，保存、查看、编辑，并经确认创建新的正式行程。

已确认：五个平台分别配置 Key、模型名和接口地址；支持手填模型名；Key 加密记住，重启后可用，可替换和删除。检索独立于模型，统一使用智谱搜索，而非各模型内置搜索。一次生成最多三次搜索、一次模型请求；失败不自动重试，不静默切换平台或退回离线知识。生成前告知发送到“智谱搜索＋所选模型平台”。

仅扩展独立网站，不动小程序，不建立跨产品账号或数据同步。本期不做花销、地图、登录、公开部署、多人共享、对话助手、自动订票、地图路径优化或多轮自动代理。现有手动行程功能继续可用，未配置 Key 不影响它。

**新增工程建议，须随本书面设计确认：AI 单次规划限 1～3 个城市、1～14 个自然日，偏好最多 1,000 字。** 城市上限使每城一次搜索对应三次调用预算；天数和文本上限限制输出和费用。只限制 AI 生成，不改变原手动行程规则；更长的 AI 行程以后另行讨论，不自动分批调用。

第一部分已经有实现和自动化测试证据，但取消删除、键盘焦点、真实请求失败重试及修复后编辑交互等浏览器验收仍未完全结束。本期不能把这些历史欠项写成通过，交付时分别报告。

## 2. 用户流程和页面

### 模型与搜索设置

新增设置页：五个平台各有模型名、HTTPS 接口地址、密码型 Key 输入框和“已配置／未配置”状态。仅展示配置状态，不回显已保存 Key 的明文或片段；留空表示保留，替换和删除是明确动作。保存设置只进行本地校验和加密，不偷偷调用模型测试。

智谱搜索使用独立的搜索配置入口。可显式选择复用已保存的智谱模型 Key，也可单独配置搜索 Key；是否拥有搜索权限由该 Key 的平台权限决定，不能仅凭“已保存”声称可用。删除被复用的 Key 后，搜索显示未配置。模型选 DeepSeek、MiMo、Kimi 或 Qwen 时仍使用智谱搜索。

用户只在本机网页输入 Key，不在聊天里发送。提示个人聊天会员或 Coding Plan 凭据不一定是相应标准 API 凭据，尤其不能将 Kimi Code Key 当作 Kimi 标准 API Key。

### AI 规划输入和生成

从网站城市目录选择 1～3 个城市及希望访问的顺序；填开始／结束日期、人数、可空人民币预算和偏好，再选平台／模型。基本字段沿用行程领域校验；AI 上限另行校验。预算使用整数分，非浮点金额。

生成按钮旁显示实际模型名、请求目的地址、智谱搜索配置及“最多 3 次搜索＋1 次模型请求；平台可能收费”。搜索只发送城市名及必要旅游偏好关键词；不发送人数、预算或完整个人输入。所选模型收到日期、人数、预算、偏好及限定的搜索资料，不收到其他行程、草稿或任何 Key 正文。自定义地址显示实际接收主机，不仅显示品牌。

提交后显示“检索资料／生成攻略／保存结果”等真实状态，不显示虚构百分比。一个数据库最多同时执行一项生成；另一标签页提交时显示已有任务，不启动第二项付费调用。刷新或重进页面可以恢复输入和任务状态，不重新触发生成。

失败保留输入和可用的检索记录，显示明确原因及已发起调用次数；允许用户主动开始新一次生成，并再次提示可能计费。不存在自动重试按钮背后偷偷多调用的行为。

### 攻略查看、编辑与转行程

输出包括标题、已校验的城市路线和日期、逐日安排、注意事项、检索来源及检索时间。按日期展示每日活动，来源集中列出；活动可引用已保存来源编号，无来源支撑的建议明确标注，不编造网址。门票、营业时间及交通等时效信息提示以官方最新公布为准。

成功结果自动保存为本机攻略。攻略列表支持再次打开；编辑可以改标题、基础信息、城市日期、每日安排及注意事项，保存有版本冲突保护。保留原生成快照和原来源；用户改动标记为“已编辑”，不声称改动内容经过再次联网验证。本期没有“AI 自动改写”，编辑不付费调用。

点击“创建行程”展示摘要，明确这是新行程；校验通过并确认后直接创建，不覆盖任何已有行程或新建草稿。一个攻略最多关联一趟新行程，同一转换重复提交返回同一行程。正式行程详情能打开转换当时的攻略快照，逐日内容不会仅因行程表只保存城市而丢失。

转换后继续编辑原攻略不会同步修改正式行程；编辑正式行程也不会重写原攻略。页面明确提示两者是独立快照，关联攻略上的路线按转换时记录展示。删除关联行程保留原攻略历史，但不允许原转换操作自动复活已删行程。复制攻略、批量导出和删除攻略暂不纳入本期。

## 3. 模块与接入边界

沿用原生前端、Node.js HTTP、SQLite，只监听 `127.0.0.1`。前端仅调用本机 API；外部 Key 解密和外部 HTTPS 请求只发生在服务端。

- 规划领域层：输入限制、输出结构、每日日期／城市／来源引用校验，纯函数。
- 凭据仓库与保护器：设置版本管理、Windows 加解密、脱敏读取，独立于模型传输。
- 搜索适配器：智谱独立搜索，转为统一来源结构，不加载来源网页。
- 模型适配器：五个平台分别处理鉴权、路径、模型参数、响应正文及用量；共有传输和结构解析，不硬套一套参数。
- 任务服务：持久化任务、调用上限、单任务互斥、故障和重启恢复。
- 攻略仓库／转换服务：版本受控编辑、完整攻略保存、幂等新行程创建。
- 页面：设置、生成输入与进度、攻略列表／详情／编辑；沿用暖色视觉，业务与布局解耦。

仅接入文本 Chat Completions 类协议，不支持任意 Responses、Anthropic 协议、图像／语音模型或任意第三方代理。手填模型名不等于保证所有模型可用。预置名字在实施时以官方文档为准，不用历史名字冒充当前推荐模型。

DeepSeek 使用官方文本接口；智谱模型接口与独立搜索接口分开；Kimi 使用标准开放平台；Qwen 地址需要支持其地域和业务空间差异。MiMo 官方页面当前为动态文档，本轮未完整核实其最新请求契约，实施计划必须把核对官方完整接口、鉴权及响应示例列为适配前置项；不能凭第三方站点或其他平台协议猜测，未核实前不标记适配通过。

接口地址允许按平台填写官方地域／业务空间地址。首版只允许已核实的平台官方 HTTPS 主机或严格官方域名规则，拒绝任意代理主机、用户名密码、片段、非标准端口、本机及内网地址；实际传输拒绝重定向，使用校验后的公网地址连接并验证 TLS 主机。修改接收主机必须重新提供 Key，不自动把旧 Key 发给新主机。官方允许列表随适配器维护，不使用任意“域名包含品牌名”检查。

## 4. Key 保存与本机安全

在 SQLite 设置记录里保存 DPAPI 密文及无敏感信息的模型配置；运行目录和数据库继续不提交 Git、不能经静态服务下载。采用 Windows `DataProtectionScope.CurrentUser`，不采用所有本机用户均可解密的机器范围，也不另外在代码里固定一把“加密密码”。

保护器通过受控的 Windows 系统能力调用；Key 不进入命令行参数、进程环境变量或日志，进程间数据只经私有标准输入输出传递，加密输出之外不回显原文。请求、异常、HTTP 访问日志均不包含 Key、Authorization、完整外部响应或行程正文。响应只提供配置状态；浏览器不使用 localStorage／sessionStorage／IndexedDB 保存 Key，保存结束清空输入框。

配置损坏、DPAPI 不可用或解密失败时显示需重新配置，不降级为明文，不清空数据库，不覆盖未知密文。一般绑定原 Windows 用户和计算机；换账户／机器可能需要重填 Key。DPAPI 不能抵御已控制同一用户账号的恶意软件，也不能撤销已发给平台的凭据；平台侧撤销须到相应控制台操作。

设置保存要求匹配配置 revision；生成中的配置锁定，服务端拒绝任何标签页替换或删除设置，避免同一任务中途更换目的地。任务完成或失败后可修改。继承 Host、Origin、JSON、请求体限制、静态白名单和 CSP 保护，详情和来源使用文本节点，禁止执行模型 HTML／脚本。

## 5. 检索、模型请求与结果验证

每个城市构造一个不超过 70 字的搜索词，含城市及必要主题。使用智谱独立 `POST https://open.bigmodel.cn/api/paas/v4/web_search`，`search_engine=search_std`、`search_intent=false`、`count=5`、`content_size=medium`；城市数即搜索请求数，最多三次，不额外请求搜索词生成、网页抽取或模型内置搜索。

搜索依次进行；任一失败或无有效来源即停止，不继续调用模型，不悄悄改用别的引擎。统一来源包含本地 sourceId、标题、合法 HTTP(S) URL、摘要、可空发布时间和检索时间。每来源摘要最多 1,200 字，最多 15 条去重来源；只筛选合规数据，不把模型提供的网址当作检索证据。不自动下载源网页，因此页面提示当前依据是搜索摘要，而非阅读全文验证。

搜索摘要和用户偏好都是不可信资料，作为有边界的数据传给模型，不能当成系统指令；不给模型执行命令、联网工具、数据库访问或 Key。仅请求一次非流式生成，要求结构化 JSON，输出 token 上限 8,192（按适配器的合法参数映射）；不自动续写、修 JSON 或再次询问模型。首次支持的模型须能在该调用方式下完成文本生成；截断或协议不支持时报告失败。

输出必须满足：基本信息与请求一致；请求中所有城市按顺序出现且无额外城市；日期满足现有路线规则；逐日覆盖整个行程且同一日期只有一条每日记录，换城日可含相邻两城活动；每个活动所属城市存在且该日属于其停留范围；引用只指向实际返回的 sourceId；预算不伪装成已发生花销。每天最多 5 项活动，每项标题最多 80 字、说明最多 150 字；注意事项最多 10 条、每条最多 200 字；可编辑内容的 UTF-8 JSON 最多 48 KiB，保存请求仍须小于原 64 KiB 限制。生成和人工编辑采用相同结构限制；异常数据拒绝保存为成功攻略，不能悄悄裁切日程。

每搜索 HTTP 超时 30 秒，模型 HTTP 超时 120 秒；单个响应读取上限 1 MiB。最多三次搜索＋一次模型是应用发起请求的上限，不是承诺实际账单金额。服务端在发送前持久记录“即将调用”，即使发送后连接断开，也按可能已计费显示；不把超时当作免费或完全没发送。收费按平台当时规则，页面不硬编码固定人民币总价。

来源链接仅允许 HTTP(S)，新窗口带 `noopener noreferrer`。有来源只证明检索得到过相关资料，不证明攻略每条事实为真；检索时间与原文发布时间分开展示。用户编辑内容同样不自动获得“已核实”标签。

## 6. 数据、重启和幂等

数据库从版本 1 迁移到版本 2，保留全部行程、城市、草稿和保存回执。停服取得独占权后，先制作一致的本机迁移备份，再在事务内加表和升级版本；失败回滚，未知或损坏数据库仍拒绝重建。此备份仅用于本次升级保护，不替代第五部分完整备份／恢复产品功能。

新增设置、AI 任务、攻略及转换记录：

- 设置：版本号、平台配置、搜索配置、Key 密文；配置读取绝不返回密文。
- 任务：id、唯一 operationId、输入及配置版本摘要、状态、阶段、已预约调用计数、来源快照、结果攻略 id、脱敏错误、创建／更新时间；不保存 Key 明文。
- 攻略：id、revision、原生成快照、当前编辑内容、来源及检索时间、平台／模型快照、时间戳、可空转换关联。原生成快照和来源不可被用户编辑覆盖。
- 转换记录：攻略 id、转换时 revision、固定目标行程 id、确认的攻略快照、转换回执及是否已删除目标标记。

任务状态为 queued → searching → generating → succeeded，任一阶段可转 failed；异常停服的未完成任务在下一次启动变为 interrupted，保留输入，不自动继续付费步骤。任务事务很短，不把 SQLite 事务横跨外部网络等待。

接收生成请求先以 operationId 和规范化输入／配置版本摘要持久化。相同操作的重复请求或丢失响应后的重发返回同一任务；同一 operationId 但内容不同返回冲突。即使配置已变，也先查询旧回执，不把读取旧状态当成新生成。另一个新任务在已有活动任务时返回冲突。

每个数据库需要进程级独占运行保护（Windows 排他文件句柄，在进程结束后由系统释放），启动必须先取得保护再迁移和恢复任务；另一个端口指向同一数据库也不得启动第二执行者。不能仅凭 lock 文件存在就认为有活进程，也不能让第二进程把第一进程任务标为中断。无法取得或建立保护时拒绝启动，不能绕过后继续付费调用。

攻略编辑使用 revision 校验，旧标签页不能覆盖新修改。转行程在单事务校验攻略版本、创建全新行程、保存关联快照和回执；失去响应后查询／重试不会再建第二趟。转换后的攻略再编辑仍返回原转换回执，不重复建行程。目标删除后旧回执显示“原行程已删除”，不重新插入。现有草稿、行程保存 CAS 和不确定保存保护不被绕开。

## 7. 本机 API 契约

沿用安全 JSON 错误体，字段错误 422，版本／并发／幂等冲突 409，记录不存在 404，外部不可用 503；不直接返回外部原始错误正文。

- `GET /api/ai/settings`：脱敏设置、配置版本、活动任务状态。
- `PUT /api/ai/settings`：版本受控配置保存、Key 替换或明确删除；不调用平台。
- `POST /api/ai/jobs`：带 operationId、输入和配置版本，持久化后返回 202 和任务 id；异步执行不能阻塞读取行程。
- `GET /api/ai/jobs`、`GET /api/ai/jobs/:id`：任务摘要／完整输入与状态，包含调用计数和可恢复结果；只读请求绝不生成。
- `GET /api/ai/plans`、`GET /api/ai/plans/:id`：攻略列表／详情与关联。
- `PUT /api/ai/plans/:id`：版本受控、领域校验的人工编辑，不调用模型。
- `POST /api/ai/plans/:id/convert`：带攻略版本，确认后幂等创建新行程，或返回既有转换／已删除状态。

原路由需支持异步错误传递及后台任务，但不重写无关行程接口。前端轮询只做 GET，页面离开不再轮询但服务端已有任务正常结束；本期不提供可能被误解为“取消后不收费”的取消按钮。

## 8. 测试、验收与完成条件

实施按独立可验收模块推进，先写测试再做功能：输入／输出与来源验证；DPAPI 与脱敏设置；各平台适配；任务持久化和次数上限；攻略编辑和转换；最后接网页。详细步骤待本规格确认后单独写实施计划。

自动化测试默认全部模拟外部传输，不使用真实 Key，不消耗平台额度。必须覆盖：五平台各自鉴权／请求／响应；非法配置与地址、重定向及内网拒绝；Key 不回显、不入日志；DPAPI 用假 Key 实测同用户重启解密和错误保护；配置冲突／任务锁；1／2／3 城请求数量；搜索空结果、超时、模型拒绝／截断／非法 JSON、未知城市和伪造来源；双标签并发；失去 POST 响应后的同操作重试；重启中断不重发；数据库版本升级／失败回滚及原行程和草稿保全；转换失败回滚、重复转换和删除后不复活。

浏览器验收使用无隐私的模拟输入：设置与 Key 输入清空、生成前披露、进度／失败输入保留、刷新恢复、来源跳转、攻略重启留存、编辑冲突、转换确认及新行程详情攻略快照；检查桌面／窄屏和键盘操作。不能用纯模型单元测试声称真实浏览器通过。

实际付费联调在功能测试后，用户自行在本机配置凭据，并明确同意用于哪组虚构旅行输入和最多调用次数后才开始。某平台没有提供 Key 时，只能报告“模拟协议测试通过／真实调用未验证”，不能声称五个平台均已实测。MiMo 若官方契约仍无法核实，应明确报告该适配受阻，不用第三方猜测补上通过结论。

交付要列出测试结果、真实 UI 证据、模拟与真实联调差别、历史和新欠项及启动说明。完成第二部分后停止，问用户是否进入花销阶段，不自动推进。
