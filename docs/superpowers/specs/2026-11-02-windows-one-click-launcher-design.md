# Windows 本机一键启动设计

日期：2026-11-02

## 意图

让同一台 Windows 电脑上的个人用户无需打开 PowerShell 或输入命令：双击桌面“智游足迹”图标后，网站在独立的 Edge 应用窗口中打开；关闭该窗口后，本机服务自动、安全停止并释放数据库锁。

## 目标

- 提供一个桌面快捷方式，一次双击即可启动服务并打开网站。
- 使用 Microsoft Edge 应用模式，窗口不显示普通浏览器地址栏。
- Edge 应用窗口退出后，由仍然拥有服务对象的 Node 启动器调用现有 `close()`，完成 HTTP、AI 作业、SQLite 和数据库锁的正常关闭。
- 启动失败时显示用户可理解的 Windows 提示，并在本地保留不含 API Key 的诊断日志。
- 保留现有 `npm start`，开发和故障排查仍可使用当前命令行方式。

## 非目标

- 不制作安装包，不引入 Electron、Tauri 或新的浏览器运行时。
- 不改成联网服务，不增加登录、云同步或手机访问。
- 不让普通浏览器的其他窗口决定服务生命周期。
- 不改变现有数据库位置、备份策略、端口安全边界或网页 UI。

## 约束

- 仅支持 Windows；当前电脑已确认存在 Edge：`C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe`。
- 继续要求 Node.js 25.9.0 或更高版本；当前 Node 位于 `C:\Program Files\nodejs\node.exe`。
- 服务仍只监听 `127.0.0.1`，默认端口仍为 `3210`。
- 快捷方式和脚本必须能处理项目路径中的中文与空格。
- 正式运行继续使用 `runtime/travel.sqlite`；验收使用独立 QA 数据库。

## 方案比较

1. **专用 Edge 应用窗口（已选择）**：启动器同时拥有服务器和专用浏览器进程，窗口关闭即可结束服务；不增加大型依赖，最符合本机单人使用。
2. **默认浏览器加页面连接监听**：浏览器更自由，但刷新、休眠、标签页切换和连接释放会让停止时机不稳定。
3. **打包桌面应用**：生命周期最可控，但安装包、依赖和维护成本明显超出当前需求。

## 结构与行为

### Node 桌面启动器

新增一个可测试的 Node 启动模块，复用 `src/start.mjs` 导出的 `startServer()`：

1. 解析项目根目录、Edge 路径、端口、数据库路径和专用 Edge 用户目录。
2. 调用 `startServer()`；只有服务器完全启动后才打开 Edge。
3. 以 `--app=http://127.0.0.1:3210/`、专用 `--user-data-dir` 和关闭首次运行提示的参数启动 Edge。
4. 等待该专用 Edge 应用进程结束。
5. 在正常关闭、Edge 启动失败、Ctrl+C 或终止信号下都调用 `running.close()`；关闭动作必须幂等。
6. 返回稳定的退出码和本地化错误类别，不输出数据库内容、API Key、请求正文或底层敏感错误。

专用 Edge 用户目录固定放在 `runtime/edge-app-profile`，使应用窗口与用户日常 Edge 会话隔离，并避免 Edge 把启动命令转交给已有普通窗口。目录属于本机运行数据，不加入 Git，也不在退出时删除。

### Windows 包装脚本

新增 PowerShell 包装脚本：

- 从脚本自身位置推导项目目录，不依赖当前工作目录。
- 检查 Node、Edge 和项目文件是否存在。
- 隐藏命令窗口运行 Node 桌面启动器。
- 失败时使用 Windows 消息框显示简短说明，并提示查看 `runtime/launcher.log`。
- 日志采用覆盖或有界策略，避免无限增长；记录时间、阶段和错误代码，不记录密钥或用户数据。

### 桌面快捷方式

提供一个安装脚本，在当前用户桌面创建“智游足迹.lnk”：

- 目标为 Windows PowerShell，使用隐藏窗口参数执行包装脚本。
- 工作目录为项目根目录。
- 重复运行时更新同名快捷方式，不创建重复图标。
- 实现完成后，在本机实际创建并验收该快捷方式。

## 异常与边界

- 找不到 Edge、Node 或关键项目文件：不启动服务，显示明确提示。
- 端口被其他程序占用或数据库已被另一实例占用：不强制结束任何进程，不破坏现有实例，显示“已在运行或端口被占用”。
- Edge 无法启动：立即正常关闭刚启动的服务并报告错误。
- Edge 崩溃或用户关闭应用窗口：正常关闭服务；短暂退出不在后台遗留 Node 进程。
- 服务关闭失败：尽力释放资源、写入脱敏日志，并返回失败状态；不得删除数据库或备份。

## 验证

- 自动化测试注入假的 `startServer` 和进程启动器，覆盖启动顺序、Edge 参数、正常关闭、启动失败、重复关闭和脱敏错误。
- PowerShell 脚本进行语法和路径含中文场景检查。
- 在隔离 QA 数据库与非默认端口上实际双击启动：确认 Edge 应用窗口打开、页面可用、无命令窗口；关闭窗口后确认端口不可访问且数据库锁可重新取得。
- 最后运行完整 `npm test` 和 `git diff --check`。
