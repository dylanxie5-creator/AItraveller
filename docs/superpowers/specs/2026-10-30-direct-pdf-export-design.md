# 智游足迹直接 PDF 导出设计

日期：2026-10-30

## 目标与原因

用户不再需要浏览器打印预览。旅行档案入口应在一次明确点击后，直接生成并下载 `.pdf` 文件；不打开打印窗口，不依赖“另存为 PDF”，也不在网站内保存导出历史。

沿用已经确认的产品规则：

- 同时支持旅行总档案和单趟档案。
- 总档案只收录已经结束的行程。
- 每次按当前数据库即时生成。
- 输出采用固定 A4 纵向版式，保留路线、攻略版本、来源、花销和足迹。
- 网页版、小程序和各自数据继续相互独立。

## 非目标与反目标

- 不提供物理打印、系统打印预览或 HTML 打印页。
- 不新增导出历史、云端存储、分享链接、邮件发送或跨设备同步。
- 不调用外部 PDF 服务，不上传旅行数据。
- 不把 PDF 生成功能建立在用户电脑中某个浏览器的安装路径或自动化能力上。
- 不把 HTML 截图当作 PDF；文字必须可选择，长内容必须真正分页。

## 已考虑的实现方式

### A. Node 服务端直接生成 PDF（已选择）

本地 Node 服务读取现有档案聚合结果，使用本地 PDF 生成库构建 A4 文档并以下载响应返回。优点是版式、分页、文件名和错误处理都由项目控制，不依赖浏览器打印设置；代价是增加一个本地运行依赖并维护一套 PDF 布局代码。

### B. 浏览器端生成 PDF

可减少服务器路由，但中文字体、长表格、内存占用和多页布局更难保持一致，且浏览器端需要加载较大的字体与生成代码，因此未选。

### C. 后台调用 Edge／Chrome 转换 HTML

最接近当前打印页面，但依赖浏览器可执行文件、版本和安装路径，启动子进程也会扩大运行边界，因此未选。

## 技术方案

### PDF 生成器

新增独立的服务端 `archive-pdf` 模块，输入只接受现有 `archive-service` 返回的不可变档案对象，输出为 PDF 字节和安全文件名。生成器不访问数据库、不发起网络请求，也不读取 API Key。

使用 PDFKit 的 Node 版本并锁定依赖版本。官方文档确认其支持 Node 流、A4 多页文本流、自动换行、表格、链接以及 TrueType／OpenType／TTC 字体嵌入：[PDFKit 官方站点](https://pdfkit.org/)、[官方文本与字体说明](https://github.com/foliojs/pdfkit/blob/master/docs/text.md)、[官方表格说明](https://pdfkit.org/docs/table.html)。PDFKit 使用 MIT 许可证，版本与许可证写入 `THIRD_PARTY_NOTICES.md`。

本项目已经限定 Windows 和 Node.js 25.9。中文字体按以下顺序只从本机读取：

1. `C:\Windows\Fonts\msyh.ttc`；
2. `C:\Windows\Fonts\msyhbd.ttc` 用于标题（不存在时复用常规字体）；
3. 若常规字体缺失，返回受控的 `PDF_FONT_UNAVAILABLE` 错误，不生成乱码或空白文件。

字体只嵌入生成的本地个人档案，不复制进项目仓库。生成器通过可注入的字体路径和 PDF 文档工厂保持可测试。

### 文档结构

总档案：

1. 封面：标题、收录截止日期、生成时间、数据库版本。
2. 卷首总览：行程、天数、花销、省市与到访统计。
3. 年度目录、分类汇总、城市花销。
4. 每趟已结束行程独立起页。
5. 全部足迹索引。

单趟档案：

1. 行程封面与路线摘要。
2. 城市路线。
3. 攻略当前版、转换快照、模型原始输出及检索来源。
4. 花销汇总、分类／城市统计和逐笔明细。
5. 足迹与备注。

固定版式使用 A4 纵向、统一页边距、页眉／页码、暖色手账色板。每个章节在写入前估算最小所需高度，无法容纳时主动换页；长段落交给 PDFKit 自动换行。花销明细使用重复表头，单元格按内容高度计算，避免裁切和重叠。来源 URL 作为可点击链接，同时以可换行文本显示。

### HTTP 下载接口

保留现有 JSON 档案接口供聚合与测试使用，新增：

- `GET /api/archive.pdf`
- `GET /api/archive/trips/:id.pdf`

请求到达时读取一次当前档案快照并生成 PDF。成功响应包含：

- `Content-Type: application/pdf`
- `Content-Disposition: attachment`，同时提供固定 ASCII 回退名和 RFC 5987 UTF-8 中文文件名
- 精确 `Content-Length`
- `Cache-Control: no-store`

文件名沿用：

- `旅行总档案-截至YYYY-MM-DD.pdf`
- `旅行档案-行程名称-结束日期.pdf`

行程名称只参与编码后的下载文件名，移除控制字符和 Windows 禁用字符并限制长度，不能注入响应头。未结束行程继续返回现有受控冲突；不存在返回 404。字体缺失、生成失败或超过 64 MiB 时返回本地安全错误，不返回半个 PDF，也不暴露路径、堆栈或内部库错误。

生成过程先在内存中完成并通过 `%PDF-` 文件头、非空页集合和大小上限校验，再写响应头，因此失败时仍能返回正常 JSON 错误。个人本地档案的预期规模远小于上限；不在磁盘留下临时 PDF。

### 网页交互

- “旅行档案”页把“预览旅行总档案”改为“下载旅行总档案 PDF”，链接直接指向 `/api/archive.pdf`，使用浏览器原生下载行为。
- 已结束行程详情把“导出行程档案”改为“下载行程档案 PDF”，链接指向对应单趟接口。
- 未结束行程仍只显示“行程结束后可生成档案”。
- 删除打印预览路由、打印按钮和 `window.print()` 调用；旧 `#/reports/.../print` 地址回退到旅行档案页，不再打开打印界面。
- 下载不写数据库，不新增“已导出”状态。浏览器接收到附件后由用户选择如何保管；网站不宣称文件已保存成功。

为避免失败时把 JSON 错误页当作 PDF 下载，下载动作使用一个小型同源控制器：按钮点击后进入“正在生成 PDF…”状态，通过 `fetch` 检查状态和 `application/pdf`，再创建临时 Blob URL 触发下载并立即撤销。失败时在当前页面显示本地错误并允许重试；重复点击在进行中只发出一次请求。Blob、URL 和错误信息不持久化。

## 安全与隐私

- 生成器只处理本机聚合数据，不连接远程字体、图片、来源页面或 PDF 服务。
- PDF 中的来源只作为已有 HTTP(S) 链接写入，不抓取页面内容。
- HTTP 仍受现有 Host、Origin、路径解码和同源策略保护。
- 下载文件不包含模型 Key、地图密钥、数据库路径、备份路径或内部 ID 之外的敏感配置。
- 响应和错误继续使用 `no-store` 与 `nosniff`。

## 测试与验收

### 自动化

- 生成器：总档案、单趟、空章节、长中文、长备注、长 URL、多页花销表、非法文件名字符、字体缺失、大小上限。
- HTTP：PDF 魔数、MIME、附件文件名、长度、无缓存、404／未结束／生成失败，以及无半响应。
- 前端：两个下载入口、进行中防重复、成功 Blob 下载、错误保留与重试、旧打印路由不再可达。
- 回归：现有档案聚合、花销、足迹、AI 与数据库测试全部继续通过。

### 当前运行验收

使用隔离 QA 数据库从总档案和单趟档案各下载一次。用 `pdfinfo`／`pypdf` 检查页数、元数据和可提取中文文本；用 Poppler 把每页渲染为 PNG，检查封面、章节分页、表格重复表头、长备注、链接文字、页码及无乱码／重叠。确认浏览器没有出现系统打印窗口，也没有修改正式数据库。

## 兼容与迁移

数据库结构和现有数据不变，不需要迁移。新增 `pdfkit` 后，首次取得代码需要执行 `npm install`；README 的“无第三方运行依赖／不需要 npm install”会同步更新。`package-lock.json` 必须提交以锁定可复现版本。

旧打印预览只是网页路由，不是已保存数据；删除它不会影响档案内容或历史记录。现有 JSON 档案接口继续保留，便于未来调整布局时复用同一聚合契约。

## 完成标准

- 用户点击总档案或单趟档案下载后得到可打开的 PDF，不出现打印预览。
- PDF 中文可读、可选择，固定 A4 分页无裁切、遮挡或黑方块。
- 长内容和空章节如实输出，所有现有收录规则不变。
- 失败在当前页面可见且可重试，不下载伪 PDF。
- 不保存导出历史、不修改数据库、不进行外部网络调用。
