# 智游足迹网页版：中国足迹地图设计规格

日期：2026-10-17

状态：四部分产品设计已由用户逐项确认；本文用于最终整体复核，尚未开始功能代码实现。

## 1. 目标与范围

在现有本地网页版中增加独立的中国城市到访记录和足迹地图。已结束行程中的城市可以自动形成足迹；用户也可以补录过去的旅行。全国视图按省级行政区展示点亮状态，省份详情展示到访城市，城市详情展示多次到访、关联行程和城市花销。

本阶段继续保持本地单用户边界：数据只进入当前 SQLite 数据库，服务只监听 `127.0.0.1`，不与微信小程序互通，不新增登录、云同步、分享、导航或当前定位。足迹模块不把行程名称、日期、备注或花销发送给地图服务。

首版仅覆盖现有城市目录中的中国境内城市。国外地图、运动轨迹、照片相册、好友排行、公开主页和将“整个行程”花销分摊到城市均不在本阶段。

## 2. 已确认的产品规则

- 自动足迹以行程城市的离开日期为准；只有 `departureDate < 服务端今天` 时才点亮，今天离开或未来离开的城市都不点亮。
- 每趟行程、每个城市形成一条独立到访记录。同一城市在不同旅程中出现时保留多条记录，并展示到访次数、各次日期和关联行程。
- 手动历史记录支持只填年份、年份与月份、完整日期三种精度，并可填写简短备注。
- 修改已结束行程时，仍与行程关联的自动足迹同步城市、日期和行程名称快照；城市被移除或离开日期改为今天/未来时，该关联自动足迹不再保留。
- 删除整趟行程前，自动足迹转为独立历史记录并保留城市、日期和行程名称快照；删除行程不能顺带抹除旅行历史。
- 用户可以单独撤销自动足迹。撤销会保存抑制记录，后续自动同步不会把它重新创建；用户可以主动恢复。
- 全国视图以省份为点亮单位；一个省只要有一个到访城市就算点亮。点击省份查看到访城市，不在全国视图绘制全部城市边界。
- 城市详情显示与当前仍存在行程关联的城市花销。只统计明确归属该城市的花销，“整个行程”花销不自动分摊；已删除行程和手动记录没有可追溯花销时明确显示无关联数据。

## 3. 选定方案与合规边界

采用“本地足迹领域 + 受控在线地图适配器 + 完整列表降级”方案。足迹记录、统计和详情均由本地服务计算；在线地图只负责合规底图、行政区边界和标记显示。首个提供商确定为高德地图 JS API 2.0，其官方 `DistrictSearch` 支持按行政区编码取得边界并用多边形覆盖物着色。不使用小程序分支中仅供测试的 DataV GeoAtlas 数据，也不从不明来源下载 GeoJSON。

第一版只允许代码内审核过的地图提供商和固定官方域名，不允许用户填写任意脚本、瓦片或接口地址。第一版提供商固定为高德，不显示没有实际实现的选择项；用户填写自己的 Web 端（JS API）Key 和安全密钥。其他提供商必须另做接口、条款和显示核验后才能加入白名单。

官方文档核验已确认高德 `DistrictSearch` 可按行政区名称或 `adcode` 返回行政区边界坐标，并可用 `AMap.Polygon` 绘制。实施时仍须用用户测试 Key 完成真实接口验收；若当前 Key 类型、权限或服务条款下无法取得边界，则不得用来源不明的数据补齐，应暂停地图图形发布并保留完整省市列表。全国省级着色是正式验收项，不能以手绘近似轮廓冒充完成。

公开部署前必须核实并按提供商及主管部门要求显示地图来源、版权和审图号。自然资源部标准地图服务说明指出，直接使用标准地图需要标注审图号，而编辑地图内容后公开使用可能需要送审；本产品的动态着色不假定属于“未经编辑直接使用”。本地开发版不等于已获得公开发布资格。

## 4. 数据模型与数据库迁移

### 4.1 数据库版本

数据库从 v3 升级到 v4。新数据库直接创建完整 v4 结构；已有 v1、v2 或 v3 数据库继续按顺序迁移，但在首次结构修改前只生成一份原始数据库的原生、已验证备份。

迁移必须经过来源版本/结构验证、SQLite 原生备份校验、单事务 DDL、目标结构验证、`quick_check` 和外键检查。备份、迁移或验证失败时拒绝启动并保持原数据库不变；失败产物不能标记为有效备份。

### 4.2 `footprint_visits`

每次到访保存：

```text
id: string, primary key
revision: positive integer
city_code: catalog city code
city_name: city-name snapshot
province_code: catalog province code
province_name: province-name snapshot
date_precision: trip_range | year | month | day
date_start: YYYY-MM-DD for trip_range/day, YYYY-MM for month, YYYY for year
date_end: YYYY-MM-DD only for trip_range, otherwise null
source: trip | manual | detached
linked_trip_id: nullable foreign key -> trips(id)
trip_name_snapshot: nullable bounded string
note: string, at most 200 Unicode characters
created_at: ISO timestamp
updated_at: ISO timestamp
```

`trip` 来源必须有 `linked_trip_id`，使用城市到达/离开日期构成 `trip_range`；`manual` 来源不得伪造关联行程；删除行程时转换成 `detached` 并清空外键，但保留日期和行程名称快照。部分唯一索引保证仍关联状态下 `(linked_trip_id, city_code)` 只有一条自动到访。所有新城市编码由服务端目录解析，客户端提交的城市、省份名称均不可信。

手动日期不虚构月或日：年份、月份和完整日期按原精度保存与展示。排序使用可比较的规范值与稳定的更新时间、ID 次序；不同精度相同时不声称知道更精确的先后。

### 4.3 `footprint_suppressions`

撤销自动足迹保存 `(trip_id, city_code)`、创建时间和操作回执标识，组合键唯一并通过外键随整趟行程删除。同步器遇到抑制记录时不创建该自动足迹。恢复操作删除抑制记录并重新执行资格判断；只有当前行程城市已满足完成条件时才恢复为可见足迹。

手动足迹删除采用实体删除，不创建抑制记录。已脱离行程的历史足迹不再参与自动同步，可由用户单独编辑备注或删除。

### 4.4 `map_settings`

地图设置使用单行、带版本的记录保存固定提供商代码、分别加密的 Web 端 JS API Key 与安全密钥、创建/更新时间和 `revision`。来源、官方域名、版权和审图信息由代码内高德适配器提供，不能由浏览器自由填写，以免把任意来源伪装成已审核提供商。两项凭据只保存 Windows CurrentUser 加密后的密文；不存在明文回退。

Key 和安全密钥分别使用 `replace | retain | delete` 明确操作；首次配置必须同时提供两项，删除任一项后地图状态为“未完整配置”。损坏密文不自动删除，公开读取也不返回密文；用户可以通过明确的成对替换或删除操作恢复。未来如增加提供商，切换时不得转移隐藏凭据。

### 4.5 操作回执

足迹写命令复用项目现有的幂等命令模式：操作 ID、实体/行程身份、请求摘要和有界响应持久化。丢失响应后重发完全相同的命令不会重复创建、撤销或删除；同一操作 ID 携带不同负载时返回冲突。

## 5. 同步与行程生命周期

`footprint-sync-service` 接收服务端当天日期，按 `(tripId, cityCode)` 计算期望状态：

1. 城市仍属于行程、`departureDate < today` 且没有抑制记录时，创建或更新关联自动足迹。
2. 城市被移除、离开日期为今天/未来或行程不再满足约束时，删除仍关联的自动足迹。
3. 不修改手动或已经脱离行程的历史记录。
4. 重复执行结果相同，不制造第二条记录，也不改变无关记录。

同步在以下位置运行：

- 服务启动完成、开始监听前执行一次。
- 首页或足迹页加载时，前端先调用幂等的 `POST /api/footprints/sync`，随后读取总览；因此服务跨过午夜但未重启时也能及时点亮。
- 行程新建或修改事务中，在行程数据写入后同步该行程。
- 足迹恢复命令中同步对应行程和城市。

删除行程使用扩展后的行程生命周期服务，在同一个数据库事务内先同步当前状态，再将关联自动足迹改为 `detached`、保留快照，最后删除行程。现有草稿、AI 转换状态、花销和分类仍按既有规则处理；任一步失败则全部回滚，不能出现行程已删但足迹未脱离或相反的状态。

## 6. 统计与花销派生

足迹表只存每次到访，不冗余保存城市到访次数、已点亮省份或合计花销。服务端按有效到访记录派生：

- 已到访省份数：存在至少一条到访记录的唯一省代码数。
- 已到访城市数：唯一城市代码数。
- 总到访次数：到访记录总数。
- 城市次数：该城市的到访记录数。
- 城市花销：仍有关联行程的到访记录所对应行程中、`expense.city_code` 等于该城市的金额总和。

一个行程内城市不重复，因此同一笔城市花销只对应一条当前关联足迹。城市详情按行程列出花销小计，并显示总计；`city_code IS NULL` 的“整个行程”花销始终单列说明、不得分摊。删除行程后其花销按现有外键规则清理，脱离后的足迹只保留历史快照，不保留过时金额。

## 7. 模块边界

- `footprint-validation`：日期精度、备注、实体版本和写命令校验。
- `footprint-store`：到访、抑制、回执和持久化行验证。
- `footprint-sync-service`：从正式行程计算并同步自动足迹。
- `footprint-statistics`：省市次数、城市明细和城市花销派生，不修改输入。
- `footprint-service`：组合行程、花销与足迹存储，提供事务级业务命令。
- `footprint-api-router`：本机同源 JSON API、错误映射和请求限制。
- `map-settings-store`：地图提供商、加密 Key、配置版本和公开安全视图。
- `map-provider-adapter`：固定高德官方域名、脚本加载、行政区边界与城市标记；不能读写足迹数据库。
- `amap-security-proxy`：按高德官方安全模式将浏览器的固定前缀请求转发到固定高德服务并在服务端附加安全密钥；不接受自定义上游地址。
- `footprint-controller` / `footprint-views`：路由生命周期、交互状态和安全渲染。

地图适配器失败只能影响图形区域，不能改变足迹记录、统计或列表。外部脚本不得获得服务端数据库接口或 AI 凭据。

## 8. API 契约

- `POST /api/footprints/sync`：按服务端今天执行幂等同步，只返回同步后的计数摘要。
- `GET /api/footprints`：返回省、市和总到访统计、可搜索的省市列表及地图可用状态。
- `GET /api/footprints/cities/:cityCode`：返回城市快照、按时间倒序的到访记录、关联行程与城市花销。
- `PUT /api/footprints/visits/:visitId`：以客户端生成 ID、操作 ID 和预期版本新增或编辑手动/已脱离记录；关联自动记录只允许修改个人备注。
- `DELETE /api/footprints/visits/:visitId`：只删除手动或已脱离记录；请求必须携带操作 ID 和预期版本。关联自动记录必须走明确的撤销接口，不能伪装成普通删除。
- `PUT /api/footprints/suppressions/:tripId/:cityCode`：明确撤销关联自动足迹。
- `DELETE /api/footprints/suppressions/:tripId/:cityCode`：明确恢复资格，随后重新同步。
- `GET /api/map-settings`：返回固定提供商、Key/安全密钥是否分别配置、显示所需合规元数据和配置版本，不返回完整凭据。
- `PUT /api/map-settings`：保存 Key 与安全密钥的明确操作，沿用现有加密、版本冲突和敏感日志保护。
- `GET /api/map-session`：仅足迹页按需获取浏览器加载配置；返回 JS API Key 和本机 `/_AMapService` 代理地址，但不返回安全密钥。JS API Key 因浏览器地图协议而可见，不得进入日志、错误、HTML 静态文件或仓库。
- `/_AMapService/*`：只转发高德 JS API 安全模式所需的受限请求，在服务端解密并附加安全密钥；限制方法、路径、查询和响应体，禁用重定向与重试，失败只返回本地错误。

所有写请求继续执行现有 Host、同源 Origin、JSON 内容类型、64 KiB 请求体和原型/访问器防护。记录不存在、归属不符、版本冲突、字段错误和地图配置错误使用不同的稳定错误代码。

## 9. 页面与交互

### 9.1 导航与首页

侧边导航增加“足迹地图”。首页增加真实足迹摘要，显示已到访省份、城市和到访次数；没有记录时显示明确空状态，不显示假数字或模拟点亮。

### 9.2 足迹总览

页面顶部展示三项统计和“补录足迹”入口；主体包含在线中国地图与始终可用的省市列表。列表支持按省份分组及城市搜索，是正式功能而不是只在报错时出现的占位。

存在至少一个到访城市的省份使用统一暖色高亮。点击省级区域或列表项进入该省视图，展示已到访城市、各城市次数和城市花销。点击城市标记或城市列表项进入同一个城市详情，避免地图与列表形成两套行为。

### 9.3 城市详情

城市详情按日期倒序展示每次到访：日期/日期范围、自动/手动/已脱离来源、关联行程或行程名称快照、个人备注和该关联行程中的城市花销。页面同时显示到访次数、城市花销总计和“整个行程花销未计入”的说明。

### 9.4 手动补录与管理

补录表单使用现有 344 项城市目录搜索，选择年份、月份或完整日期精度，并填写短备注。手动记录和已脱离记录支持编辑、二次确认删除；自动记录的城市和日期只能通过编辑原行程改变，但允许单独编辑个人备注、撤销和恢复。

字段错误邻近显示并聚焦首个错误；保存期间阻止重复提交。失败或版本冲突时保留输入，不自动覆盖另一标签页的新版本。

### 9.5 地图设置与降级

独立设置页展示固定的高德提供商、JS API Key/安全密钥各自的配置状态、来源、审图号/版权字段、域名白名单及额度提醒。浏览器地图 Key 必然可能在开发者工具网络请求中看到，界面不得把它描述为完全保密；安全密钥通过本机服务代理保留在服务端。建议用户使用高德控制台的域名限制和最小调用额度。

未配置 Key、断网、官方脚本被拦截、边界接口失败或审图信息缺失时，地图区域显示局部错误与设置入口，统计、列表、详情和手动管理继续可用。页面不申请定位权限，不读取当前位置。

## 10. 地图数据与隐私

地图调用只可包含公开的行政区编码、标准行政区名称或展示所需坐标，不得包含到访次数、行程名称、旅行日期、备注、预算、花销或 AI 内容。若提供商仅凭编码即可完成请求，优先使用编码；使用标准名称时也不得把它与用户是否到访组合进请求参数。

行政区边界、中心点和底图必须来自选定提供商已授权且适用于当前用途的服务。不能把第三方返回数据批量抓取后重新打包为本地边界资产，除非其许可明确允许且公开使用要求已经满足。响应仅用于当前地图显示；缓存策略服从提供商条款。

内容安全策略只放行高德适配器所需的精确 HTTPS 域名。JS API Key 与安全密钥使用与 AI 设置相同等级的 Windows CurrentUser 加密存储，公开设置读取只返回各自的 `configured`；地图会话只向浏览器提供 JS API Key，安全密钥由受限本机代理使用。服务器和浏览器控制台均不得主动打印任一凭据。

## 11. 错误处理与一致性

- 同步、撤销、恢复、编辑和删除均可安全重试；不确定响应继续使用原操作 ID。
- 数据库写入在事务中完成；失败整体回滚，不留下半条足迹、孤立抑制或被提前删除的行程。
- 读取或统计失败显示错误与重试，不把失败伪装成“尚未去过”。
- 地图错误与足迹领域错误隔离；地图脚本不能触发足迹写入。
- 日期以服务端本地日历日计算，前端传入的“今天”不参与资格判断。
- 旧路由的延迟响应不能覆盖当前页面；页面离开后停止地图监听和异步渲染。
- 损坏记录、未知数据库版本、备份失败或迁移验证失败时拒绝启动，不静默跳过或重建。
- 日志只记录操作类型、稳定错误代码和提供商代码，不记录地图 Key、城市到访信息、备注、行程名称或金额。

## 12. 测试与验收

自动化测试至少覆盖：

- 新建 v4 数据库，以及 v1/v2/v3 到 v4 的原始备份、逐级迁移、回滚和结构验证。
- 离开日期早于今天自动点亮；今天和未来不点亮；服务跨日后的同步。
- 行程编辑带来的新增、更新、移除和回到未来日期；重复同步不重复记录。
- 删除行程在同一事务中脱离足迹并保留快照；事务故障不会部分提交。
- 撤销、抑制、防止重建、恢复和随行程删除清理抑制。
- 同城多次到访、手动年/月/日精度、备注、排序、版本冲突和幂等回执。
- 省市次数、唯一统计、关联行程与城市花销；“整个行程”金额绝不分摊。
- API 归属、方法、同源写保护、体积限制、错误映射和敏感数据不泄漏。
- 地图提供商白名单、固定 HTTPS 域名、Key 加密/删除/切换、无 Key 与加载失败降级。
- 地图适配器只接收允许的公开行政标识，不接收足迹明细或花销。
- 前端路由、搜索、表单、删除确认、撤销恢复、延迟响应隔离和响应式布局。

浏览器验收使用独立 QA 数据库，不连接 AI 或其他付费接口。至少验证：已结束/今天离开/未来行程；两个行程重复到访同城；手动年/月/日补录；行程修改和删除；撤销与恢复；城市花销和整趟花销排除；无 Key、错误 Key/断网降级；刷新与服务重启持久化；桌面宽屏和约 390px 窄屏；Console 无应用错误。

真实地图验收另设发布门槛：使用用户自己的测试 Key，在提供商允许的域名和额度内检查全国边界、省级着色、港澳台及附属岛屿等完整显示、来源/版权/审图号可见和交互一致。未通过该门槛时只能交付“足迹数据与列表已完成、地图待合规验证”的本地测试状态，不能宣称正式地图已完成或公开部署。

## 13. 完成标准

- 用户能从行程自动获得到期足迹，并能补录、编辑、撤销、恢复和删除历史记录。
- 删除行程后足迹仍在，编辑行程后关联足迹保持一致，同城多次到访独立可查。
- 全国省份点亮、省份到城市下钻、城市详情和花销统计符合已确认规则。
- 地图不可用时，列表与全部管理功能仍可完成同样的核心任务。
- 数据库升级安全，所有既有行程、AI 和花销测试继续通过。
- 地图服务来源、Key 使用、审图号显示和公开发布边界有真实证据，不使用测试专用或来源不明地图资产。
- 自动化测试、宽窄屏浏览器验收、README 和验收记录完成后暂停，由用户决定是否进入个人版收尾。
