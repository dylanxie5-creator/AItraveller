# 智游足迹网页版全站 UI／交互统一设计

日期：2026-10-30  
状态：视觉方向与本文设计已由用户批准；尚未进入产品代码修改。

## 1. 意图与背景

现有网页版的核心功能已经完整：行程管理、AI 攻略、花销、足迹地图、数据备份恢复和旅行档案均可用，并通过完整自动化测试。当前问题主要集中在体验层，而不是功能缺失：

- 各阶段逐步加入了独立页面，虽然共用暖色变量，但卡片、工具栏、表单、空状态和操作区的视觉规则并不完全一致。
- 窄屏导航依赖横向滚动，重要入口可能被藏在视口外；页面底部多按钮在窄屏上可能拥挤或重叠。
- 禁用、处理中、危险和次要操作的视觉差异不够稳定。
- 数据安全和旅行档案等后加入页面的部分动态元素缺少完整可访问名称。
- 当前“所有内容都放进暖色卡片”的方式削弱了页面层级，也使长期使用时的视觉密度偏高。

本阶段把网站统一为一套现代、克制、可长期使用的私人旅行年鉴。用户选择了第一套“纸上旅程”方向，并确认采用加入 React Bits 交互语言后的修订版。

## 2. 用户与成功标准

本网站仍只服务当前电脑上的单个用户。使用场景是反复查看和维护自己的旅行资料，而不是一次性展示页。

改造成功的判断标准：

1. 从概览、行程、AI、花销、足迹、数据安全到档案页，用户能明显感到是一套产品。
2. 页头最多有一个清晰主操作；每个独立操作分组最多有一个实心主按钮。次要、返回、危险和不可用操作不用阅读文案也能初步区分。
3. 桌面端保留安静的旅行年鉴感；窄屏不再依赖横向滚动才能找到主要导航。
4. 交互动效用于表达位置、层级和状态，不影响输入、阅读和低性能设备。
5. 键盘、屏幕阅读器、200% 缩放和 `prefers-reduced-motion` 用户仍可完整完成主要流程。
6. 不改变任何业务规则、数据格式、安全边界、API 或打印档案内容。

## 3. 范围与非目标

### 3.1 本阶段包含

- 全局设计令牌、字体层级、间距、边框、圆角、阴影和状态色统一。
- 桌面侧栏、顶栏、窄屏导航和页面标题区重做。
- 按钮、链接、表单控件、步骤条、状态徽标、列表、空状态、加载和错误状态统一。
- 首页、行程列表／详情／编辑、AI 全流程、花销、足迹、地图设置、数据安全、旅行档案入口页的界面更新。
- React Bits 风格交互的原生 CSS／JavaScript 等价实现。
- 键盘、焦点、可访问名称、动效降级和三档响应式验收。
- 生成并本地保存一份通用的水墨旅行页眉装饰资源；不根据用户数据或城市动态生成图片。

### 3.2 本阶段不包含

- 不改微信小程序。
- 不新增登录、分享、云同步、互联网部署、社交或多人协作。
- 不增加天气、酒店、预订、通知中心、推荐流或统计图表。
- 不改变地图供应商、AI 平台、备份机制或数据库结构。
- 不重做旅行档案 PDF 的分页与内容模型；打印页面只同步基础字体和颜色，不加入屏幕动效。
- 不为 344 个城市制作独立插画，也不把第三方图片或字体放进页面。

### 3.3 反目标

以下结果即使“更炫”也视为失败：

- 把私人旅行手账做成企业后台、赛博控制台或营销落地页。
- 让动效掩盖状态、阻塞操作、导致布局位移或频繁重播。
- 依赖悬停才能理解按钮或导航；触屏和键盘体验不得降级。
- 为了使用组件库而迁移整个技术栈、引入构建器或增加外部 CDN。
- 每个区域都使用发光、玻璃、粒子、3D 倾斜或动画，造成视觉噪声。

## 4. 方案比较与选择

### 方案 A：只微调现有 CSS

保留现有结构，只替换颜色、圆角和间距。优点是改动小、风险低；缺点是无法根治窄屏导航、卡片层级、页面操作区和跨模块一致性问题。本阶段不采用。

### 方案 B：迁移 React 并直接安装 React Bits

把前端改为 React，再直接安装 React Bits 组件。优点是可以原样使用库组件；缺点是需要重写现有原生视图、控制器和测试基础，引入 React、构建工具以及组件依赖。对本机单用户产品来说收益不足，且会扩大数据安全与回归范围。本阶段不采用。

### 方案 C：旅行年鉴视觉系统＋原生交互实现（已选择）

保留原生 HTML／CSS／JavaScript 与现有控制器，只抽象全局视觉和交互层。参考 React Bits 的交互特征，但不复制 React 运行时组件：

- [Line Sidebar](https://reactbits.dev/components/line-sidebar)：侧栏活动轨道与指针邻近反馈。
- [Spotlight Card](https://reactbits.dev/components/spotlight-card)：主要内容表面的柔和指针聚光。
- [Counter](https://reactbits.dev/components/counter)：概览数字变化时的滚动过渡。
- [Stepper](https://reactbits.dev/components/stepper)：行程创建三步流程的统一轨道和内容过渡。
- [Fade Content](https://reactbits.dev/animations/fade-content)：路由进入和长列表首次进入视口时的短促淡入。

选择理由：能实现用户选定的视觉方向，并保持现有无依赖、本地运行、容易验证的架构。实现只借鉴交互行为与视觉语言，不复制 React 源码；若以后直接采用任何上游代码，必须单独记录其 MIT＋Commons Clause 许可和来源。

## 5. 视觉系统

### 5.1 色彩

保留温度，但不再让所有组件都呈同一种米黄卡片：

- 页面底色：象牙纸白，作为大面积阅读背景。
- 主要文字：墨黑／深咖，保证正文和标题对比。
- 主操作：陶土橙，用于唯一主按钮、活动轨道和关键数字。
- 完成／足迹：低饱和苔绿色，同时配合文字或图标，不只依赖颜色。
- 辅助强调：暗金／茶褐，只用于细分隔和装饰标记。
- 表面：瓷白为主；浅暖表面只给状态提示、空状态和分区背景。
- 危险：稳定的深红与浅红底；不得与主操作共用相同填充色。

所有文字、控件、边框和焦点色需达到 WCAG 2.2 AA 的相应对比要求；实际数值在实施计划中通过浏览器计算后固化为令牌。

### 5.2 字体与层级

- 不加载远程字体；继续使用系统中文字体栈。
- 页面标题为年鉴式高对比层级，但应用页不使用营销式超大标语。
- 正文保持 15–16px，说明文字最低 13px，行高 1.55–1.7。
- 金额、日期和计数使用等宽数字特性。
- 英文眉题只作次级定位，不承担唯一信息。

### 5.3 空间、边框与表面

- 先用间距、对齐、字体和细分隔线分组，再使用背景和边框。
- 页面主区域不再全部套卡片；只把可独立操作或需要聚焦的对象做成表面。
- 常规圆角 8–12px，输入和按钮 8–10px；不使用大面积胶囊形控件。
- 阴影只给浮层和主要可交互表面，静态内容优先使用 1px 边界。

### 5.4 图标与装饰资产

- 导航和常用操作使用同一套本地开源线性图标，禁止继续混用字符、表情符号或临时手绘图标；不使用 CDN。
- 页眉使用一份由图像生成工具制作的通用中国山水／旅行邮戳透明装饰，不包含具体城市、真实人物、品牌或远程内容。
- 装饰必须 `aria-hidden`，不得占据关键文字位置；低带宽和打印模式可以完全隐藏。

## 6. 全局框架与导航

### 6.1 桌面（≥ 1000px）

- 左侧固定侧栏宽约 248px；品牌、导航和本地个人版身份区域保持稳定。
- 使用一条垂直活动轨道串联导航项。当前项由轨道节点、左侧标记、背景和字重共同表达。
- 指针靠近导航项时，只做不超过 4px 的水平位移和文字强调；点击区域本身不移动。
- 顶栏只保留一句产品语气文案和“本地个人版”状态，不承载业务操作。
- 主内容宽度上限约 1200px，详情与表单页使用更窄的阅读宽度。

### 6.2 中等宽度（720–999px）

- 侧栏缩为约 208px，隐藏英文副标题和非必要装饰；导航标签仍完整显示。
- 双栏内容降为单栏或 2:1 布局，不产生横向滚动。

### 6.3 窄屏（< 720px）

- 取消顶部横向滚动导航。
- 页面底部固定四项主导航：概览、行程、足迹、更多。
- “更多”打开可关闭的底部抽屉，包含旅行档案、AI 攻略、地图设置、模型设置和数据安全。
- 花销继续保持“当前行程有效”的既有边界，不新增全局花销导航；从概览摘要或具体行程详情进入。
- 抽屉支持 Escape、焦点圈定、点击遮罩关闭；关闭后焦点返回“更多”。
- 页面底部为固定导航预留安全空间，任何提交、删除或返回按钮不得被遮挡。
- 页面级主操作可在标题区换行，不使用覆盖内容的悬浮按钮。

## 7. 组件与交互规则

### 7.1 Line Sidebar 等价实现

- 仅增强导航反馈，不改变链接语义和键盘顺序。
- `pointermove` 只更新 CSS 自定义属性，不触发视图重渲染。
- 粗指针、触屏和减少动态效果时关闭邻近位移，只保留活动轨道。
- 活动状态必须同时提供 `aria-current="page"`。

### 7.2 Spotlight Surface 等价实现

- 只用于首页最近行程、行程详情概要、花销总览和足迹摘要等少数主表面。
- 聚光直径、透明度和移动速度保持克制；不使用霓虹、彩虹或高亮闪烁。
- 键盘焦点显示固定边界，不要求用户用鼠标触发聚光。
- 粗指针或减少动态效果时退化为普通瓷白表面。不做设备性能 API 或运行时帧率探测，以免产生不可重复和错误的降级判断。

### 7.3 Counter 等价实现

- 只在概览计数首次载入或数值发生变化时播放一次，时长不超过 350ms。
- 辅助技术读取完整最终数值，不逐位播报动画。
- 金额不使用滚动数字，以免影响快速核对；只对省份、城市、次数等小整数使用。

### 7.4 Stepper 等价实现

- 保留当前“基本信息—城市路线—确认保存”三步业务规则。
- 活动轨道平滑移动，内容使用短距离淡入；不得自动改变焦点。
- 当前步骤使用 `aria-current="step"`，已完成步骤有文字或勾选状态。
- 禁用步骤在视觉上明显不可操作，不能继续表现为普通白色按钮。

### 7.5 Fade Content 等价实现

- 路由主要内容首次稳定渲染时播放 160–220ms 淡入和最多 8px 位移。
- 表单输入、保存结果、错误信息和轮询更新不重复整页动画。
- 长列表只对首次进入视口的分组使用，不逐行制造延迟。

### 7.6 按钮和状态

- 每一独立操作区最多一个实心主按钮；页头最多一个主按钮。数据安全等多任务页面可以在彼此分隔的操作组内各有一个主按钮，但同一视区不得形成相互竞争的多个主 CTA。
- 次要按钮为瓷白描边；文本按钮用于返回和低优先级操作；危险按钮为浅红或深红，不与主按钮混淆。
- 处理中按钮保持宽度、显示明确动词并禁用重复提交。
- 真正不可用使用 `not-allowed`；处理中使用等待状态，二者不能共用同一种光标和文案。
- 所有按钮最小高度 44px；窄屏关键成组操作改为纵向或等宽网格。

## 8. 页面级应用

### 8.1 旅行概览

- 最近行程是主叙事，展示状态、日期、人数、预算和路线。
- 花销与足迹降为两条支持性内容带，不再重复四张统计卡和多层卡片。
- “新建行程”是唯一主操作；查看全部、查看花销和查看足迹使用文字或描边操作。
- 没有行程时保留真实空状态，不制造示例数据。

### 8.2 行程列表与详情

- 列表按时间分组，单趟行程使用轻量行／表面，不做两列卡片瀑布。
- 详情页把概要、城市路线和花销排成连续年鉴章节；桌面右侧可放章节索引，窄屏取消。
- 导出、编辑、删除、返回按主次与危险级别重新排序，窄屏不得重叠。

### 8.3 行程创建／编辑

- 使用统一 Stepper；字段、帮助、错误和保存状态有固定位置。
- 城市路线改为明确的编号轨道；上移、下移、移除的禁用状态必须可见。
- 自动保存只显示简洁状态，不用动效抢占注意。

### 8.4 AI 攻略与模型设置

- AI 攻略列表、任务状态、来源和逐日日程使用与行程相同的章节语言。
- 外部调用次数、Key 安全说明和任务失败信息保持高可见，不因美化弱化。
- 模型设置按平台分组，但减少层层边框；Key 输入框仍不回填、不显示和不提供复制。
- 生成中的轮询状态使用稳定状态标记，不使用持续旋转或粒子背景。

### 8.5 花销与分类

- 总额／预算／余额形成一条清晰摘要；分类和城市汇总使用轻量列表。
- 金额、日期和编辑／删除操作对齐；备注支持长文本换行。
- 分类管理和花销表单沿用统一输入、错误和按钮规则。

### 8.6 足迹与地图设置

- 地图为主内容，统计和省市列表为支持内容；地图失败时列表仍保持完整层级。
- 足迹数字使用 Counter；省、市和到访记录使用同一时间线语言。
- 地图凭据和失败提示保持明确；不得用装饰性图层遮盖地图供应商信息。

### 8.7 数据安全

- 强化“只保存在这台电脑”的信任信息，但减少大面积警告色。
- 备份创建、导入、下载和恢复使用明确的操作分组；恢复继续保持危险操作确认。
- 修复标题、输入框和所有按钮的可访问名称；列表按时间清楚排序。

### 8.8 旅行档案与打印

- 档案入口页采用年鉴封面语言，与概览视觉一致。
- 打印预览和 A4 文档保持静态、无聚光和无入场动画。
- 打印 CSS 继续隐藏侧栏、顶栏、按钮和装饰资产，不改变现有分页、内容完整性和建议文件名。

## 9. 技术落点

- 保留原生模块、现有 hash 路由、控制器和服务端静态文件白名单。
- 在 `styles.css` 中建立稳定设计令牌和基础组件层；足迹与档案专用 CSS 只保留真正特有规则。
- 新增一个小型、无依赖的前端交互模块，负责侧栏邻近效果、Spotlight CSS 变量、计数过渡、路由淡入和移动端“更多”抽屉生命周期。
- 交互模块必须支持 `dispose()`，路由变化后不留下监听器或继续修改旧 DOM。
- 装饰资产和图标全部本地化，并加入服务器静态白名单；CSP 不增加外部域名。
- 不触碰 SQLite、API Key、地图密钥、用户行程正文和备份文件。

## 10. 可访问性与动效边界

- 所有页面保留一个可聚焦的“跳到主要内容”链接，并修复它被 hash 路由误处理的问题。
- 导航、抽屉、步骤条、表单、确认和错误状态使用原生语义或等价 ARIA。
- 页面路由变化后，焦点移动到主标题；保存失败时移动到错误摘要或首个无效字段。
- 焦点环在浅色、深色和危险背景上都清晰可见。
- 在 200% 缩放和 390px 宽度下不产生页面级横向滚动。
- `prefers-reduced-motion: reduce` 时关闭位移、聚光跟随、数字滚动和步骤轨道动画，只保留即时状态切换。
- 所有动态内容最终状态必须存在于 DOM 文本中，不能只画在 Canvas 或伪元素里。

## 11. 验收与验证

### 11.0 浏览器支持基线

- 支持当前 Windows 上的 Codex 内置浏览器，以及当前稳定版 Chrome 和 Edge；三者均为 Chromium 内核。
- Firefox 和 Safari 不作为本阶段正式验收矩阵，不得在未验证时宣称完整兼容。
- 可以使用当前 Chromium 支持的 `inert`、`focus-visible`、CSS 自定义属性和媒体查询；仍需提供语义和键盘降级，不增加兼容层或 polyfill 依赖。

### 11.1 自动化

- 现有完整测试必须保持全绿；已知 Windows 文件符号链接权限跳过项不计为新增失败。
- 增加导航分组、`aria-current`、移动端“更多”抽屉、焦点恢复、可访问名称和减少动态效果测试。
- 增加行程详情窄屏操作不重叠、禁用按钮样式、打印模式隐藏装饰与交互层测试。
- 增加交互模块初始化／销毁幂等测试，防止重复监听器和旧路由回调。

### 11.2 浏览器

使用隔离 QA 数据库，在内置浏览器至少验收：

- 1440px 桌面：概览、行程详情、行程三步编辑、AI 攻略、足迹、数据安全、档案入口。
- 768px 中宽：侧栏、单栏降级、表单和地图列表。
- 390px 窄屏：底部导航、“更多”抽屉、详情底部操作、长备注和错误恢复。
- 仅键盘完成导航、创建行程三步、记录花销和关闭移动抽屉。
- 开启减少动态效果后，没有聚光跟随、滚动数字或位移动画。
- 打印预览仍为 A4 静态布局，未混入屏幕导航和装饰。

### 11.3 交付边界

本阶段完成时交付：设计令牌、组件规则、全部页面更新、响应式导航、动效降级、自动化测试和浏览器验收记录。真实 AI、真实地图和真实打印机行为仍按各自原有验收边界处理，不因 UI 改造宣称重新验证外部服务。

## 12. 实施顺序原则

正式实施计划应按以下依赖顺序拆分，并保持每批可独立回归：

1. 设计令牌、基础组件、图标和装饰资产。
2. 全局框架、桌面侧栏和窄屏导航。
3. 按钮、表单、步骤条、状态与原生动效模块。
4. 概览、行程与花销页面。
5. AI、足迹、数据安全和档案入口页面。
6. 打印隔离、全站无障碍、响应式和最终浏览器验收。

每一步都不得改变业务存储和外部调用次数；若视觉改造需要改动业务模型，应停止并另行设计，而不是把它混入本阶段。
