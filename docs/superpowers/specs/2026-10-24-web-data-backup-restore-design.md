# 网页版本地数据备份与恢复设计

## 目标与范围

为“智游足迹”网页版增加面向同一台电脑、同一 Windows 用户的数据安全能力。备份覆盖当前 SQLite 数据库中的全部业务数据：行程、花销、足迹、AI 攻略、任务、模型设置和地图设置。功能不承担跨设备同步；由于密钥使用 Windows DPAPI CurrentUser 加密，只有原 Windows 用户环境保证能够继续解密。

本阶段只实现备份与恢复，不修改小程序，也不引入云端存储、账户体系或定时后台常驻进程。

## 用户体验

侧边栏新增“数据安全”，路由为 `#/data`。页面展示数据库大小、上次自动备份时间和备份数量，并按时间倒序列出本机备份。

备份分为三类：

- `auto`：网站启动时检查；距离最近一次成功自动备份至少 24 小时才创建，最多保留最近 14 份。
- `manual`：用户点击创建，可填写不超过 80 个字符的备注；不会被自动轮换删除，并可下载为单个 `.sqlite` 文件。
- `pre-restore`：每次恢复前创建的安全备份；不会被自动轮换删除，并可再次用于恢复或下载。

页面支持导入本网站导出的 `.sqlite` 文件。导入成功后先作为受管理的手动备份出现在列表中，用户再明确选择“恢复”。恢复确认界面展示备份时间、类型、大小和备注，并使用第二次确认防止误操作。

恢复期间页面进入忙碌状态。成功后重新加载当前页面并显示成功提示；失败时显示可操作的安全错误，现有数据保持可用。

## 存储结构

受管理备份保存到数据库同级的 `backups/data/` 目录，与现有 `backups/pre-migration-*.sqlite` 迁移备份隔离。每个备份由不可预测 ID 命名的 `.sqlite` 文件及同 ID 的 JSON 元数据文件组成。元数据仅保存 ID、类型、创建时间、大小、校验指纹和用户备注，不保存密钥或业务内容。

所有输出先写入带随机名称的临时文件，完成 SQLite 结构校验、`quick_check`、外键校验和内容指纹计算后再原子改名。创建备份使用 Node `node:sqlite` 的在线备份能力，以包含已提交数据且不阻塞普通读取。

下载只能通过服务端已经解析出的受管理备份 ID 定位文件；客户端文件名和上传文件名都不能参与服务器路径拼接。

## 恢复流程

恢复按以下顺序执行：

1. 将导入文件流式写入受控临时目录，大小上限为 256 MiB；历史备份直接复制到随机暂存文件。
2. 以只读方式打开暂存文件，确认是当前项目支持的数据库结构，执行 SQLite 完整性及外键检查，并计算内容指纹。
3. 进入恢复互斥状态，拒绝新的写操作，等待已经进入的同步写操作结束，并关闭/取消 AI 后台任务。
4. 对当前数据库创建并验证一份 `pre-restore` 安全备份。
5. 关闭当前数据库连接，将当前数据库和可能存在的 WAL/SHM 边车文件移到随机回滚路径，再将目标文件原子切换为正式数据库。
6. 重新打开数据库，重建业务服务，并同步足迹派生数据。
7. 若重开或重建失败，删除失败目标并把原数据库及边车文件移回；再次打开原数据服务。
8. 成功后删除临时回滚文件；保留目标备份和恢复前安全备份。

HTTP 服务器和数据库所有权锁在切换期间保持存在，避免第二个进程介入。服务端以可替换的运行时上下文向请求处理器提供当前服务实例，恢复完成后新请求自动使用新数据库。

## 并发与安全

所有非读取 API 经统一写入协调器执行。恢复获得独占状态后，新写入返回明确的“正在恢复”错误；已经开始的同步写入完成后才关闭数据库。AI 任务先停止再切换数据库，避免旧任务在恢复后写回。

所有写请求继续要求本机允许的 Host、同源 Origin 和明确 Content-Type。普通请求只接受 JSON；导入接口只接受 `application/vnd.sqlite3`。导入采用流式限量读取，不把整个文件载入内存。错误响应不得包含路径、SQL、密钥、堆栈或底层数据库诊断。

数据库版本必须是应用当前支持的版本 4。旧版、未来版、损坏文件、普通 SQLite 文件、超大文件和不完整上传全部拒绝，且不得改变当前数据库。

## 恢复失败与可追溯性

每次创建、导入和恢复都只有在校验完成后才向页面报告成功。元数据缺失或与实际文件不一致的条目不作为可恢复备份展示。自动轮换只删除超出 14 份的 `auto` 文件及其元数据，不触碰 `manual`、`pre-restore` 或既有迁移备份。

恢复失败时优先回滚到切换前数据库；即使页面请求中断，磁盘上的 `pre-restore` 仍保留。服务器下次启动仍执行现有数据库校验，不会静默接受半写入文件。

## 验收标准

- 手动、自动和恢复前备份均包含完整、已提交的数据，并在服务器重启后可列出。
- 自动备份遵循至少 24 小时间隔和最多 14 份规则，不删除另外两类备份。
- 手动备份可以下载，合法下载文件可以再次导入并恢复。
- 修改或删除测试数据后，历史备份能够恢复全部业务数据和同机可解密的设置。
- 损坏、异项目、超大、未来版本和不完整文件均被拒绝，当前数据不变。
- 恢复期间并发写入被拒绝；恢复失败会回滚，服务仍可继续使用。
- 页面不会展示或泄漏 API Key，服务端错误和日志不包含敏感值或本机路径。
- 全部自动化测试通过，并使用内置浏览器完成一次创建、修改、恢复、刷新后的真实页面验收。
