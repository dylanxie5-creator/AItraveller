# 网页版 AI 规划验收记录

验收日期：2026-10-08。验收环境：Windows、本机回环地址、Node.js v25.9.0、独立数据库 `runtime/qa-ai.sqlite`。启动命令：

```powershell
node scripts/start-ai-qa.mjs --port 3211 --db runtime/qa-ai.sqlite
```

该脚本醒目标记“模拟模式”，在进程内固定注入搜索和模型结果，根本不创建真实 HTTPS 传输对象。它不会回退到真实平台，也禁止连接默认正式库 `runtime/travel.sqlite`。生产 `npm start` 不导入该脚本。

## 本次浏览器实测

- 设置：五个平台分别展示模型、官方接口和 Key 状态；未配置平台默认不强迫填 Key。DeepSeek 与智谱使用假 Key，经过生产 DPAPI `CurrentUser` 保存；保存后密码框为空，刷新也不回填。
- 生成：页面在发起前说明“最多 3 次智谱检索 + 1 次所选模型请求”和实际选择的平台。两城市模拟任务最终显示“检索 2/3、模型 1/1”，无伪百分比。
- 任务恢复：服务停止并使用同一 QA 数据库重启后，攻略、转换关系和正式行程仍可读取。
- 本机失败重试：表单提交时停止服务，页面保留名称、城市与偏好，显示本机连接错误；服务恢复后点击“按同一请求编号重试”，同一任务完成。
- 攻略与来源：逐日安排、提醒和两个来源可见；合法来源链接为新标签并带 `noopener noreferrer`。单元测试覆盖 `javascript:` 与 `data:` 地址不生成链接，页面全部使用 DOM `textContent` 创建不受信内容。
- 手工编辑：标题保存成功；活动可逐日增删且每日最多 5 项，来源编号可选；模型原快照和资料区只读。
- 并发冲突：两个标签从同一 revision 编辑；后保存的旧版本显示“内容已发生变化……当前输入仍保留”，输入确实未被覆盖。
- 转换：确认后创建新的正式行程；行程详情显示“转换时冻结快照”和“查看当前原攻略”，攻略后续编辑不覆盖正式行程。
- 响应式与键盘：桌面和 390×844 视口实测，390px 下 `body.scrollWidth=375`，无横向页面溢出；Tab 顺序依次经过跳转链接、品牌、四个主导航，编辑输入已通过 `label/for` 关联。
- 截图（不含 Key，且被 `/runtime/` 忽略）：`runtime/qa-screenshots/ai-plan-desktop.png`、`runtime/qa-screenshots/ai-plan-390px.png`。

没有在浏览器执行“确认删除行程”，因为 UI 删除属于不可撤销操作；取消删除和删除后转换状态由自动化服务测试覆盖。本次也未伪造“全部真实平台成功”。

## 数据、安全和恢复限制

- Key 只存 DPAPI 密文，不进入公开设置、日志、命令行或环境变量。换 Windows 用户、电脑或 DPAPI 状态失效后需重新填写；“已配置”不代表已验证。
- 每个任务最多按城市顺序检索 3 次、模型 1 次；预留计数先落库。响应不确定时只允许用冻结的原命令/operationId 重试，不自动更改输入或收费。
- 启动时活动任务会标为中断，不自动恢复外部调用；输入、来源和已预留次数仍可查看，用户需明确发起新任务。
- v1→v2 迁移前的一致备份位于数据库旁 `backups/pre-ai-v1-<唯一编号>.sqlite`；它不是日常备份。失败的 `.partial` 文件仅用于诊断。
- 来源是搜索摘要，不代表应用阅读全文核验；打开外链后由目标网站负责其内容和隐私。
